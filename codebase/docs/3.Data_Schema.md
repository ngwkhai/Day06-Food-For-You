## 1. Mục tiêu

Tài liệu này định nghĩa cấu trúc dữ liệu cho mock data món/quán dùng trong prototype.

Data được lưu tại:

```text
data/mock_foods.json
```

Backend sẽ đọc file này để lọc, chấm điểm và trả về 3 món/quán phù hợp cho user.

## 2. FoodItem Schema

Mỗi món ăn là một object có cấu trúc sau:

```ts
type FoodItem = {
  id: string;
  name: string;
  restaurant: string;
  price_vnd: number;
  eta_minutes: number;
  distance_km: number;
  is_hot: boolean;
  quick_to_eat_score: number;
  fullness_score: number;
  spicy_level: 0 | 1 | 2 | 3;
  tags: string[];
  trust_signal: string;
};
```

## 3. Field Description

| Field                | Type     | Required | Ví dụ                        | Mô tả                                  |
| -------------------- | -------- | -------- | ---------------------------- | -------------------------------------- |
| `id`                 | string   | Yes      | `food_01`                    | ID duy nhất của món                    |
| `name`               | string   | Yes      | `Cơm gà xối mỡ`              | Tên món ăn                             |
| `restaurant`         | string   | Yes      | `Cơm Gà Gần VinUni`          | Tên quán                               |
| `price_vnd`          | number   | Yes      | `65000`                      | Giá món, đơn vị VND                    |
| `eta_minutes`        | number   | Yes      | `25`                         | Thời gian giao dự kiến                 |
| `distance_km`        | number   | Yes      | `1.8`                        | Khoảng cách giả lập từ quán tới VinUni |
| `is_hot`             | boolean  | Yes      | `true`                       | Món có phù hợp nhu cầu ăn nóng không   |
| `quick_to_eat_score` | number   | Yes      | `4`                          | Điểm dễ ăn nhanh, từ 1 đến 5           |
| `fullness_score`     | number   | Yes      | `5`                          | Điểm độ no, từ 1 đến 5                 |
| `spicy_level`        | number   | Yes      | `0`                          | Độ cay: 0 không cay, 3 rất cay         |
| `tags`               | string[] | Yes      | `["com", "nong", "no"]`      | Tag phục vụ lọc/gợi ý                  |
| `trust_signal`       | string   | Yes      | `Rating 4.7, nhiều đơn trưa` | Tín hiệu tin cậy để hiển thị cho user  |

## 4. Quy ước giá trị

### spicy_level

| Giá trị | Ý nghĩa   |
| ------- | --------- |
| `0`     | Không cay |
| `1`     | Hơi cay   |
| `2`     | Cay vừa   |
| `3`     | Rất cay   |

Nếu user nói “không cay”, backend phải loại món có:

```text
spicy_level >= 2
```

Tùy demo, có thể loại luôn `spicy_level >= 1` nếu muốn an toàn hơn.

### quick_to_eat_score

| Giá trị | Ý nghĩa           |
| ------- | ----------------- |
| `1`     | Khó ăn nhanh      |
| `2`     | Hơi mất thời gian |
| `3`     | Trung bình        |
| `4`     | Dễ ăn nhanh       |
| `5`     | Rất dễ ăn nhanh   |

### fullness_score

| Giá trị | Ý nghĩa    |
| ------- | ---------- |
| `1`     | Ăn rất nhẹ |
| `2`     | Ăn nhẹ     |
| `3`     | No vừa     |
| `4`     | Khá no     |
| `5`     | Ăn no      |

## 6. Recommendation Rules liên quan đến data

Backend sẽ dùng data theo các bước:

### Step 1: Hard Filter

Loại món nếu vi phạm ràng buộc cứng.

```text
price_vnd > budget_vnd
eta_minutes > time_left_minutes - 10
spicy_level >= 2 nếu user không ăn cay
is_hot = false nếu user yêu cầu món nóng
```

Ví dụ:

User nói:

```text
Mình chỉ còn 35 phút, cần món nóng dưới 80k, không cay.
```

Thì backend nên lọc:

```text
price_vnd <= 80000
eta_minutes <= 25
spicy_level < 2
is_hot = true
```

Lý do `eta_minutes <= 25`: cần chừa khoảng 10 phút để nhận món và ăn.

### Step 2: Scoring

Sau hard filter, tính điểm để chọn top 3.

Gợi ý scoring:

```text
score =
  eta_score
+ budget_score
+ hot_score
+ quick_to_eat_score
+ fullness_score
+ trust_score
- risk_penalty
```

Công thức demo đơn giản:

```ts
score =
  Math.max(0, 40 - eta_minutes)
  + quick_to_eat_score * 8
  + fullness_score * 5
  + (is_hot ? 10 : 0)
  + (price_vnd <= budget_vnd ? 10 : 0)
  + trustBonus
  - riskPenalty;
```

### Step 3: Risk Level

Backend cần gắn `risk` cho mỗi món trước khi trả frontend.

```ts
type RiskLevel = "low" | "medium" | "high";
```

Quy tắc gợi ý:

| Điều kiện                               | Risk     |
| --------------------------------------- | -------- |
| `eta_minutes <= time_left_minutes - 15` | `low`    |
| `eta_minutes <= time_left_minutes - 10` | `medium` |
| `eta_minutes > time_left_minutes - 10`  | `high`   |

Món `risk = high` không nên xuất hiện trong top 3, trừ khi đang demo failure path.

## 7. Validation Rules

File `data/mock_foods.json` hợp lệ khi:

1. Có ít nhất 10 món.
2. Mỗi món có đầy đủ field bắt buộc.
3. `id` không trùng nhau.
4. `price_vnd` là số dương.
5. `eta_minutes` là số dương.
6. `distance_km` là số dương.
7. `quick_to_eat_score` nằm trong `[1, 5]`.
8. `fullness_score` nằm trong `[1, 5]`.
9. `spicy_level` nằm trong `[0, 3]`.
10. `tags` là array string.
11. `trust_signal` không rỗng.

## 8. validate_data.py gợi ý

```python
import json
from pathlib import Path

DATA_PATH = Path("mock_foods.json")

required_fields = [
    "id",
    "name",
    "restaurant",
    "price_vnd",
    "eta_minutes",
    "distance_km",
    "is_hot",
    "quick_to_eat_score",
    "fullness_score",
    "spicy_level",
    "tags",
    "trust_signal",
]

def validate_food_item(item, index):
    for field in required_fields:
        assert field in item, f"Item {index} missing field: {field}"

    assert isinstance(item["id"], str) and item["id"], f"Item {index}: invalid id"
    assert isinstance(item["name"], str) and item["name"], f"Item {index}: invalid name"
    assert isinstance(item["restaurant"], str) and item["restaurant"], f"Item {index}: invalid restaurant"
    assert isinstance(item["price_vnd"], int) and item["price_vnd"] > 0, f"Item {index}: invalid price_vnd"
    assert isinstance(item["eta_minutes"], int) and item["eta_minutes"] > 0, f"Item {index}: invalid eta_minutes"
    assert isinstance(item["distance_km"], (int, float)) and item["distance_km"] > 0, f"Item {index}: invalid distance_km"
    assert isinstance(item["is_hot"], bool), f"Item {index}: invalid is_hot"
    assert isinstance(item["quick_to_eat_score"], int) and 1 <= item["quick_to_eat_score"] <= 5, f"Item {index}: invalid quick_to_eat_score"
    assert isinstance(item["fullness_score"], int) and 1 <= item["fullness_score"] <= 5, f"Item {index}: invalid fullness_score"
    assert isinstance(item["spicy_level"], int) and 0 <= item["spicy_level"] <= 3, f"Item {index}: invalid spicy_level"
    assert isinstance(item["tags"], list), f"Item {index}: invalid tags"
    assert all(isinstance(tag, str) for tag in item["tags"]), f"Item {index}: invalid tag value"
    assert isinstance(item["trust_signal"], str) and item["trust_signal"], f"Item {index}: invalid trust_signal"

def main():
    data = json.loads(DATA_PATH.read_text(encoding="utf-8"))

    assert isinstance(data, list), "Data must be a list"
    assert len(data) >= 10, "Data must contain at least 10 food items"

    ids = set()
    for index, item in enumerate(data):
        validate_food_item(item, index)
        assert item["id"] not in ids, f"Duplicate id: {item['id']}"
        ids.add(item["id"])

    print("Data validation passed.")

if __name__ == "__main__":
    main()
```
